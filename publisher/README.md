# Portable Cognitive Iteration Publisher

Windows 双击 `start.cmd`，macOS 运行 `./start.sh`。启动会自动进入发布器目录，检查 Node.js 和目标网站依赖。首次缺少依赖、拉取后 `package.json` / `package-lock.json` 有变化、Node 原生组件环境变化或依赖无法加载时，会自动在目标仓库执行 `npm ci`；已安装且校验通过时不会重新下载。无需另外打开 PowerShell 安装网站依赖。电脑仍需预先安装包含 npm 的 Node.js（网站当前要求 22.12 或更高）。

本目录可以整体复制到其他电脑。每台电脑的仓库路径、Obsidian 路径、备份路径和模型配置保存在操作系统本地应用数据目录，不随发布器目录复制，也不进入 Git。

Windows 上会自动查找 PATH、Git for Windows 的常见安装位置和当前账户的 GitHub Desktop 自带 Git；无需保存机器专属 Git 路径。Git 检查失败时仍保留已保存的设置和文章列表，显示具体修复提示并阻止发布。更新发布器代码后关闭旧命令窗口，再重新启动。

OpenRouter 的 `deepseek/deepseek-v4.1-flash` 请求会关闭可选推理，并要求路由到支持请求参数的服务商，避免关闭推理的设置被忽略。GLM 5.3 Flash（`z-ai/glm-5.3-flash`）必须使用推理，发布器会把它设为 `low` 并使用相同的路由要求。其他模型和非 OpenRouter 服务不额外添加推理或路由参数。`finish_reason: length` 无论 JSON 是否可解析都会被拒绝，错误会包含可用的 token 用量。模型请求的超时覆盖完整响应正文读取。

每次翻译请求仍最多申请 24,000 输出 tokens，实际额度还受模型和服务商限制。正文超过 3,000 字符时，发布器会预先沿 Markdown 段落分批翻译；短文单次请求若被截断，也会改用分段。单批仍耗尽额度时，会在段落边界继续缩小；超长纯文本段落可沿完整句子拆分。代码围栏、表格、公式块和手机排版标记不会被强行切开。每批与合并后的全文都要通过完整性和结构校验，否则停止发布。极端情况下，单个无法安全拆分的块仍需人工缩短或更换模型。分段会增加模型请求次数与费用，译文质量仍须人工逐段核对。连接测试只验证小请求可用。更新发布器代码后须关闭旧命令窗口并重新启动；若复制过独立的 `publisher/` 文件夹，也须更新那份副本。

译文合并或拆开段落时，不要求与中文有完全相同的段落数量。若一个翻译批次的段落数变化，发布器会按原文 Markdown 块逐一重译并检查；单块内部允许自然分段。缺失正文、截断和关键 Markdown 结构变化仍会停止发布。逐块重译可能增加请求次数和费用，自动检查也不能代替人工核对语义。

若模型保留了文本提示词的内容、却去掉独立代码围栏，发布器会按原文块重译，再为单独的文本围栏块恢复原围栏。程序代码只有内容完全未变时才恢复围栏；空译文、空围栏正文和无法确认完整性的结果仍会停止发布。逐块重译会增加模型请求次数与费用。更新代码后须重启发布器，独立复制的发布器目录也须同步更新。

独立仓库的准备条件和启动步骤见仓库根目录 `README.md`。实际发布还需选择兼容的目标网站仓库。

首页用三个分类标签切换文章，每个标签显示该分类的文章总数；一次只显示当前分类。可按标题搜索当前分类，列表每页显示 10 篇。切换分类会清空搜索并回到第一页；刷新会保留当前分类和搜索词，文章数量变化时页码会自动调整。

发布确认窗需要明确选择网站封面：可从 Obsidian `_attachments` 中选一张并预览，也可使用分类默认封面。选中的文件名写回文章的 `coverFile` 元数据；封面若也嵌在 Obsidian 正文，发布到网站时只在封面位置显示，原始笔记不变。

`lib/article-markdown.mjs` 供发布器和网站导入脚本共用：统一正文标题层级、完整句摘要、可识别的表格导出错误、加粗与公式转义，并保留代码示例。正文三语翻译会检查表格行列结构；无法判断的表格格式会在发布前明确报错。页面排版与数学渲染由目标网站仓库负责，拉取更新后重新启动发布器即可自动准备新依赖。

发布前会为普通中文段落生成少量手机阅读排版建议，并并排显示电脑、手机宽度的正文预览。模型只返回原文中的加粗片段和句末位置；代码插入固定标记并核对原有字词、标点及顺序。标题、列表、引用、代码、链接、表格、公式、图片和已有作者加粗不会被智能排版改动。新增标记在电脑端不产生加粗或额外换行，原稿自带的加粗和段落保持原样；手机端显示重点加粗及句间留白。预览中的普通 `https://` 外链显示为可点击标题，在新标签打开；复杂 Markdown 仍以安全的简化样式展示，最终网站由 Astro 正式渲染。

确认排版或明确选择“沿用原排版”后才会进入三语生成和写入。单条模型建议无效时会说明跳过原因，保留同批有效建议；加粗范围内的错行建议会在预览时跳过，避免生成结构损坏的嵌套标记。全部建议无效或请求失败时，主按钮会改成“按原排版发布”。预览后原稿或封面变化须重新预览。Obsidian 正文不会被改写，发布器只按原流程写回元数据。译文需保留排版标记的数量、顺序和结构；仅在译文排版标记校验失败时自动重新生成一次，仍失败则停止写入，并可回到预览选择“沿用原排版并发布”。自动重试会增加一次模型请求费用。

依赖安装失败会保留设置，在页面与命令窗口显示原因，并暂停文章发布；修改仓库路径后保存设置也会准备该仓库的依赖。该准备过程不生成文章，也不 Commit / Push。`start.cmd --check-only` 可用于只验证启动环境，不打开浏览器或启动服务。
